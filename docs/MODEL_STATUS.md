# Model status: documented vs implemented

**Scope.** This page compares the monographs and `README.md` with the code at commit `c23787e`. `1A` means `Document 1A.md`, and so on. Status values: **Computed** (a solve or calculation in the repository), **Parameterised** (typed values stand in for a solve), **Closed-form** (an explicit expression, possibly anchored to literals), **Present, not wired** (code exists but is not called or not connected), **Not yet implemented** (described but absent). "Inferred" marks code read but not run.

## Reading

Today the code computes household value functions and stationary distributions through toolkit calls (`WelfareDecomposition_4Region.m:17`, `WelfareDecomposition_4Region.m:22`, `WelfareDecomposition_4Region.m:178`, `WelfareDecomposition_4Region.m:240`), an intergenerational transition operator (`Build_IntergenTransitionMatrix.m`) and a counterfactual suite (`PolicyExperiment_LeeSeshadri_4Region.m:94`). Prices, the intergenerational stage, the transition path, fertility and bargaining, the actuarial audit and the attribution layers are parameterised or closed-form, so the headline figures in the documents correspond to outputs under assumed prices where the component is parameterised, and to typed anchors where it is closed-form. Other branches (for example `launch` and `ndc`) are ahead of `main`, so this page describes `main` at `c23787e` only; it records a status, not a verdict.
